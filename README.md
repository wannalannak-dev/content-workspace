# Content Workspace (Content OS)

ฐานข้อมูลคอนเทนต์กลางของทีม: ตารางคอนเทนต์ + ปฏิทินที่ซิงก์กัน ลากวางเลื่อนวันได้ แนบรูปพรีวิวได้ ใช้งานผ่านเว็บหลายคนพร้อมกัน บันทึกอัตโนมัติ และเห็นการแก้ของเพื่อนในทีมทันที

เว็บจริง: https://content-workspace.wannalanna-k.workers.dev

## ไฟล์ในชุดนี้

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `index.html` | หน้าเว็บทั้งหมด |
| `config.js` | คีย์เชื่อมฐานข้อมูล + รายชื่อแบรนด์ (สี) แพลตฟอร์ม สถานะ ประเภทคอนเทนต์ |
| `supabase-update-v2.sql` | (รันไปแล้ว) อัปเดตจากเวอร์ชันแรก |
| `supabase-update-v4.sql` | เพิ่มช่อง TikTok + Ref ID อัตโนมัติ (เพิ่มอย่างเดียว) |
| `supabase-update-v6.sql` | หน้า Reports (ตารางข้อมูล e-commerce) + ช่องข้อความใน Page Covers (เพิ่มอย่างเดียว) |
| `supabase-update-v5.sql` | เพิ่มหน้า Page Covers (ตารางใหม่ ไม่แตะคอนเทนต์เดิม) |
| `supabase-update-v3.sql` | เพิ่มช่อง Boost workflow / Asset link / Ref ID + ประวัติการแก้ไข (เพิ่มอย่างเดียว ไม่แตะข้อมูลเดิม) |
| `templates/Content_Import_Template.xlsx` | Template Excel (ดาวน์โหลดตัวล่าสุดได้จากเว็บ: Export Excel → Download blank template) |
| `supabase-setup.sql` | ตั้งฐานข้อมูลใหม่ทั้งหมด สำหรับโปรเจกต์ Supabase ใหม่ |

ถ้าเว้นคีย์ใน `config.js` ว่างไว้ เว็บจะเปิดเป็น **โหมดทดลอง** (ข้อมูลตัวอย่าง เก็บในเบราว์เซอร์เครื่องเดียว)

## ระบบที่ใช้

- **Supabase** — ฐานข้อมูล ระบบล็อกอิน และที่เก็บรูปพรีวิว (แชร์ทั้งทีม เห็นเฉพาะคนในรายชื่อทีม)
- **GitHub** — เก็บไฟล์เว็บ
- **Cloudflare** — ดึงไฟล์จาก GitHub ขึ้นเว็บอัตโนมัติทุกครั้งที่อัปเดต

## อัปเดตหน้าเว็บ

แก้หรืออัปโหลดไฟล์ทับใน GitHub แล้วกด **Commit changes** — Cloudflare จะอัปเดตเว็บเองภายใน 1–2 นาที ข้อมูลคอนเทนต์อยู่ใน Supabase จึงไม่หาย

## เพิ่มคนเข้าทีม

1. Supabase → **SQL Editor** → รัน
   `insert into team_members (email, name) values ('new@mail.com','ชื่อ');`
   (อีเมลตัวพิมพ์เล็กทั้งหมด)
2. Supabase → **Authentication → Users → Add user → Create new user** ใส่อีเมล + ตั้งรหัสผ่าน ติ๊ก **Auto Confirm User**
3. ส่งลิงก์เว็บ + รหัสผ่านให้เพื่อน (เพื่อนเปลี่ยนรหัสภายหลังได้ด้วยการขอลิงก์ทางอีเมลจากหน้าเข้าสู่ระบบ)

เอาคนออก: `delete from team_members where email = 'old@mail.com';`

## ฟีเจอร์หลัก

- **แยกตาม Platform:** แถบปุ่มเหนือตาราง/ปฏิทิน และลิงก์ตรง เช่น `?platform=TikTok&view=calendar`
- **Today:** สรุปวันนี้ — Going live / Boost starts / Send to agency / Needs attention
- **Boost workflow:** ① Agency ตั้งแอด → ส่ง Post ID → เรา publish · ② เราโพสต์ → ส่งลิงก์ → Agency boost (มีเช็กลิสต์และเตือนอัตโนมัติ)
- **Scheduled ไม่เปลี่ยนเป็น Published เอง** — เมื่อถึงเวลาแล้วระบบจะขึ้น "Time passed – confirm Published" ให้กดยืนยัน 1 คลิก
- **Asset links:** ลิงก์ดาวน์โหลด VDO/AW หลายลิงก์ต่อชิ้น
- **Import Excel:** ตรวจข้อมูลก่อนนำเข้า แถวที่ Ref ID ซ้ำจะถูกข้าม ไม่เขียนทับของเดิม
- **History:** บันทึกทุกการสร้าง/แก้/ลบ กู้คืนได้

## หน้าต่างๆ

- **Calendar:** เฉพาะสิ่งที่ขึ้นหน้าเพจเรา (รวม Boost / Ads Setup ในวันที่เรากด Publish)
- **Agency:** ปฏิทินงานกับ Agency (📤 ส่งงาน · 🆔 รอ Post ID · 🔗 ส่งลิงก์ · 🔑 Spark code · ⚡ ช่วงแอดรัน) + Board (Our to-do / Waiting / Running / Done)
- **TikTok Hub:** ตาราง TikTok — คลิป, บัญชี (แบรนด์/KOL), Spark Ads code + วันหมดอายุ, ส่งโค้ดแล้ว, ลิงก์ดาวน์โหลด
- **Page Covers:** ปก/แบนเนอร์บนเพจ FB · YT · LINE แยกจากคอนเทนต์ทั่วไป ปกหนึ่งชิ้นแสดงทุกวันจนกว่าจะมีปกใหม่มาแทน ตั้งวัน (และเวลา) เปลี่ยนล่วงหน้าได้ ใส่วันสิ้นสุดได้ (หมดแล้วกลับไปใช้ปกเดิม) ถึงวันเปลี่ยนจะเตือนให้กด “Changed on page” เมื่อเปลี่ยนบนเพจจริงแล้ว ปกเก่าเก็บเป็นประวัติ
- **Reports:** สรุปคอนเทนต์รายเดือน (แยกแบรนด์ × แพลตฟอร์ม, สถานะ, ประเภท, งบแอด) + ตารางตัวเลข e-commerce (ช่องทางและตัวเลขปรับเองได้ที่ ⚙ Channels & numbers, นำเข้า/ส่งออก Excel ได้)
- **ตัวเลขด้านบน:** เป็นของเดือนที่เลือก (เดือนเดียวกับปฏิทิน) · ปฏิทินกรอง All / Organic / Boost & Ads ได้ · ชื่อเมนูซ้ายมือแก้ได้ที่ Settings
- **Export Excel:** เลือกช่วงวันที่ (ตามวันโพสต์) + ตัวกรอง → ไฟล์หน้าตาเดียวกับ Template แก้แล้ว Import กลับได้ (ติ๊กอัปเดตก่อนถึงจะเปลี่ยนของเดิม)

## กติกาการอัปเดตฐานข้อมูล

ตั้งแต่ v3 เป็นต้นไป ไฟล์อัปเดตทุกไฟล์จะ **เพิ่มช่องเท่านั้น** ไม่ลบ/สร้างตารางใหม่ ข้อมูลเดิมคงอยู่ครบ

## แก้แบรนด์ / แพลตฟอร์ม / สถานะ

แก้ใน `config.js` แล้วอัปโหลดทับใน GitHub คอนเทนต์เก่าที่ใช้ค่าที่ถูกลบไปแล้วจะยังแสดงอยู่ตามเดิม

## ข้อควรรู้

- ล็อกอินด้วยรหัสผ่านได้ทันที ส่วนการล็อกอินผ่านลิงก์ทางอีเมล Supabase แพ็กฟรีส่งได้ไม่กี่ฉบับต่อชั่วโมง ถ้าทีมใหญ่ขึ้นให้ตั้ง SMTP ของตัวเอง (เช่น Resend) ที่ Authentication → Emails → SMTP Settings
- รูปพรีวิวที่ใหญ่เกิน ~700KB จะถูกย่อให้อัตโนมัติก่อนอัปโหลด (รับ PNG, JPG, WebP, GIF ไม่เกิน 5MB)
- สองคนแก้ชิ้นเดียวกันพร้อมกัน → ใครกดบันทึกทีหลังเป็นค่าสุดท้าย
- การลากการ์ดในปฏิทินใช้ได้บนคอมพิวเตอร์ ถ้าใช้มือถือให้เปลี่ยนวันจากช่อง Publish ในตาราง หรือในหน้าแก้ไข
- สำรองข้อมูล: Supabase → Table Editor → `contents` → Export CSV
- โปรเจกต์ Supabase แพ็กฟรีที่ไม่มีคนใช้นานๆ อาจถูกพักไว้ เข้าไปกดเปิดใหม่ได้
- อย่าใส่อีเมลทีมจริงในไฟล์ `.sql` ที่อัปขึ้น GitHub ให้แก้ใน SQL Editor ของ Supabase โดยตรง
