# Content Workspace — คู่มือนำขึ้นเว็บ

ปฏิทิน + รายการคอนเทนต์ของทีม ใช้ผ่านเว็บได้หลายคนพร้อมกัน แก้แล้วบันทึกอัตโนมัติ และเห็นการแก้ของเพื่อนในทีมทันที

## ไฟล์ในชุดนี้

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `index.html` | หน้าเว็บ workspace ทั้งหมด |
| `config.js` | ตั้งค่า: คีย์เชื่อมฐานข้อมูล รายชื่อทีม ช่องทาง |
| `supabase-setup.sql` | สคริปต์สร้างฐานข้อมูล + สิทธิ์การเข้าถึง |
| `.github/workflows/deploy.yml` | นำเว็บขึ้น GitHub Pages อัตโนมัติทุกครั้งที่อัปเดตงาน |

ถ้ายังไม่ใส่คีย์ใน `config.js` หน้าเว็บจะเปิดเป็น **โหมดทดลอง** (ข้อมูลตัวอย่าง เก็บในเบราว์เซอร์เครื่องเดียว) ไว้ลองเล่นก่อนได้

## สิ่งที่ต้องเตรียม

1. **บัญชี Supabase** (ฐานข้อมูล + ระบบล็อกอิน) — supabase.com สมัครฟรีได้
2. **บัญชี GitHub** — เก็บโค้ด เก็บประวัติการแก้ไข และนำเว็บขึ้นอัตโนมัติด้วย GitHub Pages (ฟรี)
3. **รายชื่ออีเมลของทีม** ที่จะให้สิทธิ์เข้าใช้งาน
4. (ไม่บังคับ) **โดเมนของตัวเอง** เช่น `content.yourbrand.com`
5. (แนะนำเมื่อใช้จริง) **บริการส่งอีเมล (SMTP)** เช่น Resend, Brevo หรือ Gmail Workspace — อีเมลล็อกอินที่ Supabase ให้มาในตัวจำกัดจำนวนต่อชั่วโมงไว้ต่ำ

## ขั้นตอน

### 1) สร้างฐานข้อมูล
1. เข้า Supabase → **New project** (เลือก region Singapore จะเร็วสุดสำหรับไทย)
2. เปิด `supabase-setup.sql` แก้อีเมลทีมในส่วนท้ายไฟล์ (ข้อ 6) ให้เป็นอีเมลจริง ตัวพิมพ์เล็กทั้งหมด
3. ไปที่ **SQL Editor → New query** วางทั้งไฟล์ → **Run**

### 2) ใส่คีย์ในหน้าเว็บ
1. Supabase → **Project Settings → API** คัดลอก **Project URL** และ **anon public key**
2. ใส่ใน `config.js` ช่อง `supabaseUrl` และ `supabaseAnonKey`
3. แก้รายชื่อทีม (`team`) และช่องทาง (`channels`) ให้ตรงกับทีมจริง

> anon key ใส่ในหน้าเว็บได้ เพราะสิทธิ์อ่าน/เขียนถูกคุมด้วยกฎในฐานข้อมูล (เฉพาะอีเมลในรายชื่อทีม) — **ห้ามใส่ service_role key เด็ดขาด**

### 3) เอาขึ้น GitHub และเปิดเว็บ
**แบบไม่ต้องใช้คำสั่ง (ผ่านหน้าเว็บ GitHub)**
1. github.com → **New repository** ตั้งชื่อ เช่น `content-workspace`
2. หน้า repo ใหม่ → **uploading an existing file** → ลากไฟล์ทั้งหมดในโฟลเดอร์นี้ไปวาง → **Commit changes**
   - โฟลเดอร์ `.github` อาจถูกซ่อนในเครื่อง (Mac กด `Cmd + Shift + .` เพื่อแสดง) ต้องอัปโหลดไปด้วย ไม่งั้นเว็บจะไม่ขึ้นอัตโนมัติ
3. repo → **Settings → Pages** → ช่อง Source เลือก **GitHub Actions**
4. รอ 1–2 นาที ดูความคืบหน้าที่แท็บ **Actions** เสร็จแล้วจะได้ลิงก์ `https://<ชื่อผู้ใช้>.github.io/content-workspace/`

**แบบใช้คำสั่ง git**
```bash
cd content-workspace
git remote add origin https://github.com/<ชื่อผู้ใช้>/content-workspace.git
git push -u origin main
```
(โฟลเดอร์นี้ตั้งเป็น git repo และ commit แรกไว้ให้แล้ว)

**อัปเดตงานครั้งต่อไป**: แก้ไฟล์ แล้ว commit/push เข้า `main` (หรือแก้ไฟล์บนหน้าเว็บ GitHub แล้วกด Commit) — เว็บจะอัปเดตเองภายในไม่กี่นาที ข้อมูลคอนเทนต์ของทีมอยู่ใน Supabase จึงไม่หายตอนอัปเดตเว็บ

> ⚠️ **ระวังอีเมลทีมหลุด**: ถ้า repo เป็นแบบ Public ทุกคนเห็นไฟล์ได้ ให้แก้อีเมลทีมใน SQL Editor ของ Supabase โดยตรง อย่าแก้ในไฟล์ `supabase-setup.sql` แล้ว commit ขึ้นไป (ส่วน anon key ใน `config.js` เปิดเผยได้ตามปกติ) ถ้าต้องการให้ repo เป็น Private, GitHub Pages ต้องใช้แพ็กเสียเงิน — ทางเลือกคือเก็บ repo แบบ Private แล้วต่อเข้า Netlify, Vercel หรือ Cloudflare Pages ซึ่ง deploy จาก repo Private ได้ฟรี

### 4) บอก Supabase ว่าเว็บอยู่ที่ไหน
Supabase → **Authentication → URL Configuration**
- **Site URL**: ใส่ลิงก์เว็บจากข้อ 3
- **Redirect URLs**: ใส่ลิงก์เดียวกัน (ถ้ามีโดเมนเองให้ใส่เพิ่ม)

ถ้าข้ามขั้นนี้ ลิงก์ล็อกอินในอีเมลจะพาไปผิดที่

### 5) ทดสอบ
เปิดเว็บ → ใส่อีเมลทีม → กดลิงก์ในอีเมล → สร้างคอนเทนต์ 1 ชิ้น แล้วเปิดเว็บอีกเครื่อง/อีกเบราว์เซอร์ด้วยอีเมลอื่นในทีม ควรเห็นชิ้นเดียวกันและอัปเดตตามกันทันที

## การดูแลประจำ

- **เพิ่มคนเข้าทีม**: SQL Editor → `insert into team_members (email, name) values ('new@mail.com','ชื่อ');`
- **เอาคนออก**: `delete from team_members where email = 'old@mail.com';`
- **แก้หน้าเว็บ**: แก้ไฟล์แล้วอัปโหลดทับที่เดิม ข้อมูลอยู่ในฐานข้อมูล ไม่หาย
- **สำรองข้อมูล**: Supabase → Table Editor → `contents` → Export CSV
- **โปรเจกต์แพ็กฟรีที่ไม่มีคนใช้นาน ๆ อาจถูกพักไว้** — เข้าไปกดเปิดใหม่ได้ (เช็กเงื่อนไขล่าสุดในหน้าราคาของ Supabase)

## การทำงานของระบบ

- แก้อะไรก็บันทึกเอง (มุมบนแสดง "บันทึกแล้ว / กำลังบันทึก")
- ถ้าเน็ตหลุด จะลองบันทึกใหม่ทุก 5 วินาที
- สองคนแก้ชิ้นเดียวกันพร้อมกัน → ใครกดทีหลังเป็นค่าสุดท้าย
- หน้ารายละเอียดแสดงว่าใครแก้ล่าสุด
